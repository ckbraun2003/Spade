# Spade — consumers

Spade is a library. A consumer builds against the installed `spade::` package (`find_package(spade CONFIG)`) and the file formats Spade defines. **This is the only document in the library where a consumer's own rule series may appear.**

## KAT

KAT is a drone SDK and editor, and the consumer Spade was first built for. Spade was extracted from the KAT monorepo with its full history on 2026-09-28.

| What KAT uses | From Spade |
|---|---|
| Simulation, worlds, vehicles, sensors, rendering | the installed `spade::` targets |
| World description | the world-file format (`world_version`, owned by Core) |
| Session ring and replay | the snapshot format (`kSnapshotVersion`, owned by Core) |
| Scene description (what Kat compiles a build into) | the scene-file format (`engine/scene/scene_file.hpp`, owned by Core) |

**Format changes a consumer sees:**
- **The smoke tour flies the library Phantom** (Interface, merged `0f51c4e`).
  - The tour has 13 stills. `editor_placed_drone` comes before `editor_airflow`.
  - editor.add_drone, editor.airflow and editor.fly place the meshed Phantom, not the reference quad.
  - EditorRun sizes the grid cell to max(the records' cell, 2 × the largest proxy radius), and the inspector's row names the drone it was sized for.
  - A scene of reference quads only stays bit for bit the records.
- **The library drones wear rigid meshes** (Core, L7b2, merged `fc85801`).
  - Each drone's body, arms and motor bells are now mesh parts, with sidecars `drones/<stem>/{body,arm,bell}.spmesh`.
  - `vehicles::wear_look()` puts basic_quad's look on a spec's records.
  - A mesh drone's drag is `drag[0]`, the frozen L5 estimate.
  - `world/mesh_shapes`' rounded_box and every ring of 4m chords are now exactly symmetric. So the generator hashes, the 12 prop sidecars (bytes only) and the six drone thumbnails moved.
  - Mass is unchanged to the bit. Inertia moves by about 1e-3 relative.
  - The centre of mass moves 9-16 µm on all six drones, and the rotor and IMU mounts move with it.
- **LiveRun's fluid on a device** (Rendering, Run air on the GPU, slices 1 and 2, merged `479ef6d` and `c2aa0a2`).
  - `LiveRun::start(resolved, model, const LiveFluidMaker& fluid = {})`. The default is the CPU, unchanged and bit for bit. A `LiveFluid` has `step(discs)`, `publish(...)` and `read(MacGrid&)`.
  - `spike/airflow/live_fluid.hpp`: `GpuLiveFluid` and `gpu_live_fluid(ctx, wg)`, plus `start_live_run(resolved, model, ctx*)`, which returns `{run, cpu_because}`. It falls back to the CPU by name when the device refuses.
  - With a device, `save()` reads the fields back, and a restored run steps on the CPU.
  - Nothing uses it yet; the editor's Run air is slice 3.
- **Every film's frames are checked** (Rendering, merged `e3997db`). `write_frame()` takes a `FrameBound` and refuses a frame that fails `frame_fault()` before writing it: a non-finite half (beyond a solid block's allowed no-data halves), or a speed past 10 × the film's expected top speed (at least 10 m/s). The film then stops with "<stem>: frame K, after step S (t T): why". Every builder sets `Film::expected_speed`, and a `--case` file's run takes 2 v_h at full throttle plus the wind.
- **The solids projection on the GPU** (Physics, B5.6, merged `236bb12`). `solids_chain`'s `projection_chains(shape, layout, ProjectionSolidsPipelines, closed, wg)` and `project_with_solids(runner, ids, floor, cap)` return `GpuProjectionReport{ProjectionReport, capped}`. They are bit-equal to `project_solids()`. The health word sits in `airflow_scalars` slots 24-27 (`kSlotHealth`): residual, iterations, stalled, capped. `airflow_pcg_update` gains op 9 (p ← x). Nothing existing changes.
- **A motor mesh, the composite, and the basic quad's look** (Core, L7b1, merged `caba080`). These add to what was there. No library drone sets either option yet; that is L7b2.
  - `AirframeSpec::motor_mesh` is a `std::optional<MotorMeshSpec>{mesh, min_feature}` in the hub frame. It makes each motor a mesh record of exactly `motor.mass` at its hub.
  - `airframe_composite(spec)` returns `Result<AirframeComposite{inertia, mass}>`: compile_airframe()'s composite without the fit or the drag rule.
  - `BasicQuadParams::look` is a `std::optional<BasicQuadLook>{body_edge_radius, bell_chamfer, segments}`. It draws a basic quad as a rounded box, capped tubes and motor bells. The masses are unchanged to within rounding (the bells exactly), and it needs a drag spec.
- **flow_movie --gpu** (Rendering, G2, merged `9adbf27`). It runs a LiveRun film's fluid on GpuFluid, with no parts in the flow, for d1-hover and the case videos.
  - The cache stem is `<stem>-gpu`.
  - A non-Vulkan build refuses `--gpu` with exit 2.
  - A `--gpu` film checks each frame before caching it (`tools/flow_movie/frame_check.hpp`). The film stops on a non-finite half, or on a speed past 10 × the case's expected top speed, and names the frame and step. Since `e3997db` every film checks (see that line).
  - The C_p view is drawn only when the run model has parts in the flow.
  - `tests/d1_case.hpp`'s `d1_case(seconds, grid, parts_in_flow = true)` keeps its default.
- **The solids CG on the GPU** (Physics, B5.4, merged `ed02b9a`).
  - `airflow_pcg_scalars` gains ops 3-8, and there is a new `airflow_pcg_update` kernel.
  - `solids_chain` records five chains: setup, iteration, measure, restart and finish. The host reads only the 16-byte decision word (slots 9-12: stop, restart, iterations, stalled).
  - The region table is wired into init_solids at binding 19.
  - It is bit-equal to `solve_pcg_to()`. Nothing existing changes.
- **attach_solid_field() and the GPU preconditioner** (Physics, B5.2b, merged `f7a9a2a`).
  - **On the CPU**, `physics::airflow::attach_solid_field(s, g, bc, field)` attaches a solid field already built for g's shape, reaching `set_solids()`' state bit for bit. `set_solids()` now calls it. Behaviour is unchanged: it refuses as `check_grid()` does, and refuses a field made for another shape.
  - **On the GPU**, there's the `airflow_mg_restrict_full` kernel and `solids_chain`'s symmetric V(2,2) chain and init_solids hook. `projection_chain`'s `append_sweeps()` gains `black_first = false`, and the default records B2's commands unchanged.
- **Props on the library drones** (Core, L7c1, merged `d8640b9`).
  - **The spec:** `AirframeSpec::rotor_parts` holds `RotorPartSpec{name, role, rotor, mount, mesh, min_feature}`, where `mount` is in the hub frame at psi 0. Each compiles to a massless `PartAttach::rotor` mesh part, placed after every rigid part.
  - **What changes:** only `parts_identity()`. Mass, inertia, drag and `model_identity()` are unchanged.
  - **The library drones:** all six carry `prop[k]` on every rotor. Their sidecars are `drones/<stem>/prop_{ccw,cw}.spmesh`, pinned by hash, and `.gitattributes` marks `*.spmesh` binary.
  - **Posing and solids:** `posed_parts()` turns each prop by R_y(s_k psi). `PartFilter::rigid_only` drops them, so they never become solids.
  - **One refusal:** `add_model()` now refuses a placed library drone, because the drone has mesh parts. Place one with `add_model_with_meshes()`.
- **GpuFluid, the whole fluid step on the GPU** (Rendering, G1, merged `e34d2be`). New `spike/airflow/step_chain.hpp`, namespace `spade::airflow_gpu`:
  - `GpuFluid::create(ctx, g, bc, cfg, solids, wg)`;
  - `step(discs)` takes at most `kMaxDiscs` = 16 discs;
  - `read(g)`, `publish(origin, out)` and `shape()`;
  - `disc_records()` packs the discs on the host;
  - a new kernel, `airflow_add_increments`.

  Each step is bit-equal to the CPU's `fluid_step()` without solids. Limits until G3:
  - a SolidField with parts is refused;
  - health reports only `pressure_iterations = n_v`, with no scan for NaN or infinity and no residual.

  Nothing existing changes.
- **Region means, the solid interior and the wall load on the GPU** (Physics, B5.3 and B5.5, merged `5b34e16`). There are three new kernels: `airflow_region_mean`, `airflow_solid_velocities` and `airflow_wall_load`. New in `spike/airflow/solids_chain.hpp`:
  - `pack_region_table()` fills binding 19, and `region_partials_floats()` sizes the partials;
  - `append_region_means()` and `append_remove_region_means()` (the CG's gauge);
  - `append_solid_velocities(…, SolidInterior, wg)`;
  - `append_wall_load()` writes binding 27, with `wall_load_words(about)` before and `wall_load_of(words)` after.

  Each is bit-equal to its CPU twin. They add to what was there; nothing existing changes.
- **The smoke tour gains `editor.airflow`** (Interface, T3, merged `adcd27e`). Between `editor.add_drone` and `editor.add_objects`, the tour runs Run air on a placed quad. It waits for 12 air frames (a minute at most) and writes a 12th still, `editor_airflow.png`. A tour that counts steps or stills re-counts. `editor::Command` gains `run_air`, and `ui::cell_text()` takes an optional `max_width`. Nothing else changes.
- **A drone with mesh parts can be placed** (Core, L7b0, merged `78d4e7f`). `scene::add_model_with_meshes(scene, file, name)` re-points each mesh part's `mesh_file` to `imported/<16-hex content hash>.spmesh` relative to the scene. `scene::write_placed_meshes(scene, into, held_in)` writes those sidecars from memory, and the editor's Save and `--edit … --save` both call it. `scene::placed_mesh_file(mesh)` names one. `add_model()` still refuses mesh parts. `save_mesh_file()` now replaces its target whole, through `<path>.tmp-spade` and a rename.
- **The blade azimuth** (Physics, P11, merged `97ddfdd`). New header-only `engine/physics/blade_azimuth.hpp`: `spade::physics::advance_blade_azimuth(float& psi, float omega, float h)` and `advance_blade_azimuths(psi, rows, h)`, psi += omega h wrapped into [0, 2 pi) by subtracting `kAzimuthTwoPi`; a disabled rotor holds; bad inputs hold psi and return false. Host-held and visual (pass it to `posed_parts()`); nothing in the step reads it. Additive: nothing existing changes.
- **Generated meshes for the library drones** (Core, L7a, merged `29d7688`). New `world/mesh_shapes.hpp` (spade::world), namespace `spade::shapes`: `rounded_box`, `capped_tube`, `motor_bell` and `prop(PropMeshSpec, PropHand)`. Each returns `GeneratedMesh {mesh, min_feature}`, a closed outward mesh from `make_mesh()`. A propeller is in the hub frame (disc y = 0, blade 0 on +X), ccw for spin_dir +1 and cw for -1. The counts are bounded (`kMax*`), and a bad field is refused by name. Additive: nothing existing changes.
- **Airflow reductions sum in two levels** (Physics, B5.1, merged `34b718c`; Cameron, backlog 45d11fe). Every fixed-order airflow sum (the CG dots, remove_mean, wall loads, per-region sums) adds its 4^3 tile sums in blocks of `kReduceBlockTiles` = 256, then the block sums. A grid of at most 256 tiles (about 25^3 cells) gives the same bits as before; a larger grid's airflow results change in their last bits. A consumer pinning airflow bits on a larger grid re-pins; no API or format changes.
- **The reference quad is labelled a test fixture** (Core, L6, merged `af563e8`). In `assets/library/library.yaml` its entry is now "Reference quad (test fixture)", category `test fixtures`, listed last; its file, thumbnail and model bytes are unchanged. New: `drones/reference_quad.sources.yaml`, grading its synthetic prop tables `assumed`. A consumer that finds it by the name "Reference quad" or the category `drones` must use the new ones; one that loads it by path is unaffected.
- **The CPU airflow step runs with subnormals flushed; the engine's airflow builds only on x86-64** (Physics, merged `1130608`). `fluid_step`, `spread_actuator`, `wall_load` and `publish_render_volume` each set MXCSR to FTZ|DAZ, round-to-nearest, all exceptions masked (0x9FC0) for their duration and restore the caller's word whole on return (`engine/core/detail/flush_subnormals.hpp`, internal); the step's sticky flags are discarded. No digest or record moved: the shipped cases raise no subnormal. A build for a non-x86-64 target now stops with an #error rather than compiling a CPU step that can't match the GPU.
- **fp32_math.slang has exact division and sqrt; `log32_div` is gone** (Core, merged `5d3adfa`). `div32_ftz(a, b)` and `sqrt32_ftz(x)` return divss/sqrtss's bits under FTZ|DAZ, NaN bits included (Rendering's device gate: 0 differing bits over 39.8e9 results on the 3060 Ti). `log32` now divides with `div32_ftz`; its results are unchanged. A shader that called `log32_div` calls `div32_ftz`. SPIR-V rules E1/E2 as restated (Cameron, 2026-10-22) allow the device's OpFDiv/InverseSqrt only as the estimate inside these, and the scan traces each to an integer.
- **Drone sources sidecars; the default library's six drones; basic_quad hovers slower** (Core, L5, merged `addbf28`). New format `drones/*.sources.yaml` (`engine/scene/model_sources.hpp`: `to_yaml`, `from_yaml`, `load`, a check against the sources registry), pinning the model's bytes and citing each value's grade. Only the default library's own tests refuse a drone whose sidecar is missing or stale; projects and Save to library load without one. `basic_quad_airframe()`'s defaults are now the library's part files bit for bit (the tri-blade prop tables), so its default hover moves from 8189 to 6659 rpm. `fit_remainder()` is public. The Crazyflie's `cf_7x16_coreless` resistance is 1.19 ohm (was 1.6), fitted to Bitcraze's loaded top row, and `cf_1s_250`'s cutoff is 3.0 V (assumed; was 3.3).
- **The solids CG can end `stalled`; `capped` means the cap was reached** (Physics, P2d, merged `a4ec57f`). `FluidHealth` gains `stalled`: past the floor, a solve that makes no new 10% low in 4 measurements restarts once from the true residual, and stops as stalled at the next stall. `capped` now means only that the iteration cap was reached above the mark; each unconverged solids step is exactly one of the two, and `unconverged` stays their union. An exact-zero break above the mark is stalled (it used to print "at its cap of N" with N below the cap). A stop above the mark returns the iterate that measured least, not the last (one more float a cell of CG memory). Converging solves and plan A are bit-identical.
- **The default library has 22 part files; basic_quad's motor spins up faster** (Core, L4, merged `46df001`). `assets/library/parts/`: 5 props, 6 motors, 6 ESCs, 5 batteries, each in library.yaml v2 with a thumbnail and every field graded and cited (`assumed` values carry their basis). `basic_quad_airframe()`'s default `motor.rotor_inertia` is 2.7e-6 kg m^2 (was 1e-5, an unsourced placeholder): with the prop's inertia the total falls from 2.25e-5 to 1.52e-5, so its spin-up is about 32% faster. No golden held the old value.
- **The editor imports glTF; a run's solids come from the parts kept** (Interface, N15, merged `2a64c54`). Load from file takes .gltf/.glb as an object or as a drone's parts (one part per mesh), staged in `<temp>/spade-editor-imports/<token>` per workspace; Save copies the staged files beside the scene. `LiveRun` decides whether a run has solids from the parts it keeps, so a model whose parts are all drawn-only flies bit-for-bit as one without them, and a too-thin imported solid is refused with the advice to mark it visual-only. The editor's pick is refined to 0.1 mm, so placed objects no longer float 7-9 mm.
- **The solids pressure solve converges in fewer iterations; solids results shift within their bands** (Physics, P2c, merged `fac368b`). The multigrid preconditioner's coarse faces now take their fine planes' means in series, so a run with rigid parts in the flow needs about 8-9 CG iterations instead of 20-31 and steps about twice as fast; its velocities and pressures differ in the low digits (every validation record within its band). Runs with no solids (plan A) are bit-identical.
- **Library entries carry thumbnails** (Interface, N14b, merged `9d0bc80`). Each entry in assets/library/library.yaml now has `thumbnail: "thumbnails/<stem>.png"` (a key already in the v1/v2 format), and load_library() checks the named file exists. The PNGs are 96x96 RGBA, stored (uncompressed) deflate; an installed library carries the thumbnails/ folder. New entries get theirs from Interface's generator in the same commit.
- **Editor text commands `add-model-file` and `add-object-file`; the Library panel lists library.yaml** (Interface, N14a, merged `94a54c9`). The editor places a *.model.yaml or *.object.yaml by path through Core's scene::add_model()/add_object() (EDT-002 text forms); the Library panel lists the project library by category, built-in demo scenes no longer appear in it, and part kinds are inspect-only. A placed vehicle's start pose is its design frame: the body sits at to_body_state(design, design_to_principal, com_offset), so a drone rests on its lowest posed part.
- **Odd-sized airflow grids converge; the pressure solve reports its count** (Physics, merged `3995803`). Any grid with an odd axis, or whose halving would stop above 1024 cells, gets a deeper multigrid hierarchy and different, converged results (D1, the tour chapter's box, LiveRun boxes, the films); every other grid is bit-identical. With solids, `kSolidsCgIterations` is now the CG's floor: it runs on to max|r|/max|b| <= 1e-4, capped at `FluidConfig::cg_cap` (32), and "unconverged" now means the cap was reached. `FluidHealth::pressure_iterations` and `capped`, `ProjectionReport::iterations` are added. Plan A (no solids) reports its residual every step and announces it above 7.1e-2. `check_grid_note()` names a hierarchy whose coarsest level stays large. API changes are additions with defaults.
- **Part files and library index version 2** (library L2, merged `1c65501`). `scene/part_file.hpp`: `*.motor.yaml`, `*.prop.yaml`, `*.esc.yaml` and `*.battery.yaml`, each the airframe builder's block as a file plus a `sources:` map citing every field (checked against `sources.yaml`). `scene/library.hpp`: the index is version 2 (`kLibraryVersion = 2`) and reads versions 1 and 2; the four part kinds are known by suffix; `load_library_part()`, `load_library_sources()`, `check_library_contents()`. An older build refuses a version 2 index as `schema_mismatch`; a version 1 index naming a part file is refused by name.
- **A case pins its model's propulsion chain; LiveRun takes the chain from the model** (INT-11, Interface, merged `962fa02`). **CHANGED, the case file is version 2:** `model:` gains `propulsion:` (`propulsion_identity()` of the model's chain as a quoted `"0x%016x"` string after `parts:`, 0 for none), and a top-level `power:` between `controls:` and `flight:` holds `idle` and `state_of_charge`, both optional (written `power: {}` when empty). `resolve()` fills absent ones with Physics' defaults, 0.05 and 1.0, reported as `Source::default_value`. It refuses an idle outside [0, 1), a state of charge outside (0, 1], an idle at or above the model's hover duty ("armed at zero throttle the drone would climb"), and a propulsion pin that does not match the model's chain ("re-pin"). A version-1 file is refused as `schema_mismatch` ("re-save with version 2"), never migrated. `analysis::pin_model(file, model)` sets all three pins, and `load_case_model(case, case_file)` reads the case's model file beside it and checks all three. **API change:** `LivePropulsion` is gone. `LiveRun::start(resolved, model)`, `LiveRun::restore(file, resolved, model)` and `showcase_trim(c, model)` take the chain from `ModelType::propulsion` and the idle and state of charge from the case's `Power`. `spade_analysis` links `spade::scene` PRIVATE. For Kat: by its analysis ABI's own rule, the new keys and version are a MAJOR bump. Its case schema must take them, and `kat_analysis_repin` must set the propulsion pin (the lead sent Kat the list).
- **The library's sources registry** (library L1, merged `61724be`). `assets/library/sources.yaml` lists every source the library's numbers may cite, each with a license (`public_domain`, `facts_cite` or `not_usable`) and its evidence; `SOURCES.md` is its readable twin. `scene/library_sources.hpp`: `Grade` (measured, published, retailer, derived, fitted, assumed), `License`, `SourceRef`, `check_source_ref()`. A value citing a `not_usable` source (APC, and Kat's APC-shaped catalog props) is refused by name.
- **GPU device limits and the VRAM budget** (B0, merged `91ecdcb`). `compute/backend.hpp`: `DeviceReport.limits`. `compute/device_limits.hpp`: `check_buffer`, `check_storage_buffers`, `check_push`, `check_groups`, `check_workgroup`, and `vram_cap`/`check_vram` (min(4 GiB, budget - usage - reserve), refused by name as `capacity_exceeded` before any allocation). `VulkanContext::memory_budget()` (VK_EXT_memory_budget, else half the heap). `bindings.slang` gains descriptor set 1, "airflow" (`gen::kSet_airflow`, `kBinding_airflow_*`, `kBindingCount_airflow`), append-only and read by no step kernel; set 0, the mirror and every identity are unchanged.
- **GL create() cold start** (Rendering, merged `155cabc`). `render_gl/gl_renderer.hpp`: a cold `GlRenderer::create()` (driver shader cache empty) takes 4-6 s in the foreground, down from about 10 s, and 0.8-0.9 s with `flow_programs_in_background`, the flow layers ready about 3-4 s later. A warm create() with the background option costs about 250 ms, the price of the driver's parallel compile (about 19 ms without it). A third overload, `create(..., CreateProbe)`, takes a shader source salt and a per-program callback, for measurement only.
- **OBJ polygons** (B7b, merged `464c936`). `world/mesh_import.hpp` `read_obj()`: a face of more than 3 vertices is fanned from its first corner, keeping its winding, when it is planar (every corner within `kObjPlanarTolerance` = 1e-3 of the face's width) and strictly convex. Any other face is unavailable, naming its line and its first bad corner, "(triangulate on export)". Before B7b every face of more than 3 vertices was refused.
- **A live run's parts are solids in the air** (Interface, merged `491c08e`). `analysis/live_run.hpp`: when the model has rigid parts, `LiveRun::start()` poses them at the hover (`PartFilter::rigid_only`) and sets them as the grid's solids; a rotor's own parts stay the disc's. A part the grid cannot hold (below 2 dx, or leaking) fails `start()`, naming the part, so a host running a coarse grid clears the parts on purpose, as the tour's 32^3 chapter does. `LiveRun::solids()` gives `{any, run_line, solid_cells, pressure_residual, unconverged_steps}`; `run_label()` carries the solids line, and an unconverged pressure is announced on `run_line()`, never refused. A model with no rigid parts runs exactly as before.
- **Wall load and closed-face gradients** (P3, merged `cf83678`). `physics/airflow/wall_load.hpp`: `wall_load(grid, solids, regions, about)` gives the pressure force (N) and moment (N m) the air puts on all the solids together, summed in the fixed tile order; per-part loads wait for D4. `physics/airflow/publish.hpp`: `PublishInput::theta` carries the face apertures, so a velocity gradient never differences across a wall or a sheet. **For LiveRun (Interface):** when publishing with solids, pass `publish.solid` (`s.regions.solid`) and `publish.theta` (`s.solids.theta`); without them the published vorticity, Q and lambda2 mix the two sides of a sheet.
- **Scene v5: airflow regions** (N5b, merged `b3657c6`). `scene/scene_file.hpp`: `SceneDesc::airflow`, a list of `SceneAirflowRegion`.
  - A region has a name, a kind and a coupling.
    - A follow region follows a vehicle and may have a `floor`; its faces are open, set by its flight.
    - A fixed region has a `min_corner` and six faces: open, periodic or a wall with a velocity.
    - Every region has `cells` as a `physics::airflow::GridShape`, the wind as `faces.ambient`, and `density` and `kinematic_viscosity`.
    - `coupling` is `one_way` only until Physics' D4; `two_way` is refused.
  - `validate_scene()` checks each region by name and its grid with `physics::airflow::check_grid(cells, faces, true)`. It keeps that function's message and code (`capacity_exceeded` comes through), and refuses two fixed regions that overlap.
  - `region_identity(region)` is FNV-1a 64 over the region's item text: the end-goal round trip's "region" identity.
  - **What a v4 reader sees:**
    - A scene with no region is written exactly as before (v1 to v4, byte for byte), so older builds and Kat read it unchanged.
    - A scene with a region is written as version 5. An older build refuses it as `schema_mismatch`, "scene file is schema version 5, this build reads versions 1 to 4 only".
    - In a file of v4 or older, `airflow` is an unknown key: "unknown key 'airflow' in scene -- scene schema v4 does not define it".
  - Region names are unique among regions only; they share no namespace with assets or vehicles.
  - **For Interface:** renaming or removing a vehicle that a region follows is refused by the validator ("follows 'X', which is no vehicle of the scene"). The edits in `sandbox/editor_scene_edits.hpp` do not yet carry `follows` along.
- **LiveRun's rotor rows** (Interface, merged `ca48317`). `analysis/live_run.hpp`: `LiveRun::rotor_rows()` gives each rotor's row after the last step, in the model's rotor order (speed, k_T, radius, and hub and axis in the body), for a host's probes. It is empty for a model without rotors. Additive.
- **A mesh_ref never holds a scheme** (a clarification of N3's line, since `63b2f46`; in batch 11, `3a43967d`; found by Kat's PB11). `world/mesh_ref.hpp`'s rule refuses any ref holding a `:`, so a scheme-prefixed ref such as `mesh:track/gate-ring` is refused by every validator (`validate_asset`, and `validate_world_desc`'s visual_refs and props), and with it the world that holds it: "it holds a ':', as a drive or a scheme would". A mesh_ref is a relative path under the roots the caller passes to `resolve_meshes()`; a caller with its own naming maps it to that path before calling Spade (for example, `mesh:family/name` to `family/name` under the caller's mesh root). Worlds can be passed from memory: `world_from_yaml(std::string_view)` and `WorldBuilder`.
- **visual_refs are meshes only** (since N3, `63b2f46`; asked by Kat's PB11). `WorldDesc::visual_refs` (world/builder.hpp) holds render-only MESH references, each a mesh_ref, and Rendering's resolver looks every one up as a mesh. It has no non-mesh form: a `material:...` or any other entry is refused like a bad mesh_ref. A world's materials are `WorldDesc::materials`, by index.
- **Mesh import reads binary STL and OBJ** (B7, merged `2aafac1`). `world/mesh_import.hpp`: `read_stl()` and `read_obj()`, each with the MeshUnit the caller declares (an unspecified unit is refused before the file is opened). A new installed target, `spade::analysis`, which links `spade::vehicles` and `spade::physics`. `analysis/case.hpp` is the CFD analysis case Kat's builder reads and writes. `AnalysisCase` pins its model by file, `model_identity()` and `parts_identity()`, and holds the controls, flight, fluid, grid, each rotor's blade definition and airfoil polars, the time and the outputs. `case_issues()` lists every problem with its field. `case_to_yaml()` / `case_from_yaml()` / `load_case()` / `save_case()` read and write the `.case.yaml` (`version: 1`, canonical text; an unknown key or another version is refused). `resolve()` fills the defaults, sizes the grid, and builds the drone box's boundary conditions (`physics::airflow::DomainBc`: the wind as ambient, the floor as a wall, still in hover and rolling in forward flight). It refuses by field: a changed model (`model.identity`) or changed parts (`model.parts`) until re-pinned, a grid over the byte cap, and a wall part thinner than two finest cells. `analysis/coefficients.hpp` adds `rotor_coefficients()`, which returns C_T, C_Q, C_P and FM in hover, or J and eta in forward flight, in the rotorcraft or propeller convention, each with its definition, and `pressure_coefficient()`.
- **Analysis runs** (`INT-7`, W2a/W2b, merged `5654780`). `analysis/run.hpp`: `run_folder()` / `create_run_folder()` (`runs/<case>/<date>_<hash16>_<commit12>`, refused if it exists), and `RunProgress` with `read_progress()` / `write_progress()`. progress.yaml is replaced atomically, so a host polling it never reads a torn file. `analysis/runner.hpp`: `run_case()`, the loop the runner tool drives. It writes progress.yaml, history.csv (each column with its unit) and log.txt, and ends done, cancelled (the host makes the folder's `cancel` file; the results are partial) or faulted (named). The process side, launch(), the runner tool and the queue, lands with W2c.
- **Snapshot format v2** (module API stage 1, merged `062e1fa`). The header grows to 40 bytes and carries the configuration identity: the module set, versions and compiled order. A v1 blob is refused with the version message. A blob restores only into a simulation with the same identity (`L2`). KAT passes blobs through without parsing them, so a KAT session ring that holds v1 blobs cannot restore them after the upgrade.
- **Module API stage 3** (merged `42b352a`). The standard module set gains an `environment` module and a `dryden.sample` pass, so its configuration identity changes. A snapshot taken before this merge is refused on restore. The snapshot format itself is unchanged.
- **Design frame** (drone builder, Task B, merged `7532259`). A model type carries its design frame: `design_to_principal` and `com_offset`. `spawn` takes and `vehicle_state` returns poses in the design frame. The default is the identity frame, which changes nothing bit for bit.
- **Snapshot format v3** (drone builder, Task C, merged `7d46b6d`). The header grows to 48 bytes and carries the model registry's identity: each registered model's identity (`vehicles::model_identity`) in registration order. A blob restores only into a Simulation that has registered the same models in the same order. Register them before `restore()`, even in a fresh Simulation. A v2 blob is refused with the version message.
- **Scene file** (drone builder, Task D, merged `43eac56`). A new format: a scene holds a world reference plus placed assets and vehicles. It names its world by `world_hash()`, and composing it against another world is refused (`SCN-001`). Its text is canonical (`SCN-002`). Models register in the scene's `models` order (`SCN-005`). The first golden is `tests/golden/scenes/gate_run.scene.yaml`.
- **The airframe compile** (drone builder, `DBP-44`, merged `58abbf4`). `vehicles/airframe_compile.hpp` turns a part-built `AirframeSpec` (design frame, Kat's part-block units) into a `ModelType` in its principal body frame: `compile_airframe()`, `check_airframe()` (every problem in one list) and `airframe_propulsion_chain()`. A 4-in-1 ESC's `current_total` caps the drive current over its channels (`DBP-26`). Until a list of ESC boards lands, a total needs `channels` equal to the rotor count. The reference quad's `model_identity` is pinned and reproduced on gcc.
- **`ModelType::issues()`** (merged `58abbf4`). The installed `vehicles/model_type.hpp` gains `ModelIssue` and `issues()`, which list every problem with its element, index and field. `validate()` returns the first of them, with unchanged messages. `physics/forces.hpp` gains `DragLawCheck` and `check_drag_law()`. Both doors now run `check_drag_law()`: `ModelType::validate()` (and so `register_model()`) and `Simulation::add_drag_element` refuse a negative or non-finite area or coefficient, which they used to accept. One drag message changed: validate()'s "coeffs and local_pos must be finite" became one message per field (the drag law's own reasons for mode, area and coeffs, and a separate local_pos message).
- **UTF-8 paths in messages** (merged with `core/path-text-utf8`). Error messages name file paths in UTF-8 on every platform (`spade::path_text`, `core/path_text.hpp`). No file loader throws while reporting one: `load_gltf` used to throw `std::system_error` for a path outside the ANSI code page on Windows, and now returns `io_error`.
- **GPU admission and banded parity** (the user's ruling of 2026-10-05; merged `e146575`). Any Vulkan 1.1+ device is admitted, whatever its fp32 denormal support (`CORE-5`); no kernel requests a denormal mode (SPIR-V `P3`). `Simulation::vulkan_device_report()` (and `compute::DeviceReport` / `describe()`) says which device, driver and float settings produced a Vulkan run (`L6`). GPU results are banded against the CPU, not bit-identical (`TD-14`): about 0.01% relative at worst in-horizon, positions within micrometres, and in long or chaotic runs the two paths drift apart as any two float implementations do. Each path is deterministic on its own (CPU across MSVC and gcc; GPU per device and driver), and the CPU is the reference.
- **The IMU feels contact** (`PHY-7`). The accelerometer's specific force includes the contact response: a body resting on the ground reads `+g` up, not about 0, and an impact reads its full reaction, with no range clamp (thousands of m/s² on a hard landing). In-flight readings are unchanged. Every scene with contact has new digests. The reported velocity at rest still reads about `-g·dt` until `PHY-8`.
- **Module API stage 4: modules own their state** (merged `9763b93..`, stage 4 complete). The installed `sim/module.hpp` gains `ArrayDecl`/`Extent`, `StreamDecl`, `ConfigTableDecl`, `VehicleRows`, `ScratchDecl`, `QuantityAccess::optional` and `PassDecl::before`. `Simulation` gains `attach_row`, `module_rows<T>`, `module_array` and `config_table`. `SubstepContext::state` gives passes views of their declared state, and `StepShape` gains `arrays` and `scratch`. The standard `<module>.state` tokens are renamed (e.g. `dryden.dryden`), and `create()` refuses a set that drops or reshapes a built-in array or stream. Snapshot format stays v3; identity, schema hash and goldens are unchanged, so stored blobs still restore.
- **A misused module view poisons the Simulation** (module API stage 5 Task 1). A pass that reads its declared state with the wrong row type, for a world outside the set, or with the wrong accessor no longer gets a silent empty view: the step runs to its end and `step()` refuses, naming the module, pass and array. From then on every `step()` and `snapshot()` refuses with "state invalid since tick N: ..." until a successful `restore()` or a fresh `create()`; reads stay open. `table_rows<T>(view)` (no world) and `all_rows<T>(view)` are new in the installed `sim/state_view.hpp`. The standard set never misuses a view, so nothing changes for it.
- **`FlowVolumeHeader` gains `extrapolated_cells`**: the cells inside a solid that were written from their fluid side (so `C_p` on a surface reads wall pressure), at most `nx·ny·nz`; `validate_flow_volume` refuses a larger count by name. It is 0 for a volume with no solids.
- **Triangle mesh type** (`CORE-6`). The installed `world/mesh.hpp` adds `MeshUnit`, `mesh_unit_scale()`, `MeshInput`, `TriangleMesh` and `make_mesh()`. Only `make_mesh()` builds a mesh: it needs a declared unit, stores fp32 metres rounded once, and refuses by name, with counts, any mesh that is not a closed, oriented, 2-manifold solid. `content_hash()` is FNV-1a 64. Nothing folds it or reads a mesh yet.
- **Per-part model geometry** (`CORE-7`). The installed `vehicles/model_type.hpp` now includes `vehicles/model_part.hpp`: `PartAttach`, `PartSurface` (wall or porous; coefficients finite and ≥ 0, both 0 on a wall), `PartDesc` and `kNoPart`, and `ModelType::parts`, empty by default. `ModelIssue` gains `code` and `Element::part`, so an exhaustive switch over `ModelIssue::Element` needs a case for it. `validate()` returns the first issue's code: `capacity_exceeded` for a part shape deeper than `kMaxSdfDepth`. `register_model()` refuses a bad part by index, name and field, including an unbounded shape and a `min_feature` that is not finite and > 0. Parts are not folded into `model_identity` yet, so every identity and every stored v3 blob holds.
- **`vehicles::parts_identity(model)`**: the parts' own identity (geometry, mounts, surface, `min_feature`), a fixed constant when there are none, identical across toolchains. `model_identity` never folds parts; a CFD case pins both.
- **Posing a model's parts** (`CORE-7`). `vehicles/part_pose.hpp`: `posed_parts()`, `posed_program()` (the wall parts as one world-frame `SdfProgram`), `part_wall_velocity()`, `part_sample()` and `sample_parts()` (distance, owner, surface kind and wall velocity; a tie goes to the lower part index). `compose_transform` now lives in `world/builder.hpp`; `spade::scene::compose_transform` still names it, bit for bit.
- **A mesh as a part** (`CORE-6`, B4). `PartDesc` gains `mesh`, a `std::shared_ptr<const TriangleMesh>`. A part's geometry is exactly one of `shape` and `mesh`; otherwise it is refused at `shape`, naming the part. `part_sample()` (now in `vehicles/model_part.hpp`) returns the same `SdfSample` for either form, in the part frame. `posed_program()` refuses a mesh wall part by name; use `sample_parts()`. Not folded into the identity.
- **The airframe compile emits parts.** `PartInertia` gains `geometry` (`PartGeometrySpec`: source, name, role). A sphere, box, cylinder or tube record, and a shaped motor, ESC or battery block, becomes a body-frame wall part, with `min_feature` set to its smallest dimension. A propeller never does, and `source = none` opts a record out. Mass, inertia, drag and the reference quad's identity are unchanged.
- **Scene file v2** (`CORE-7`). A scene whose models have parts is written as `scene_version: 2`, with a `parts` list per model (`tests/golden/scenes/parts.scene.yaml`). A scene without parts is still version 1, byte for byte. This build reads both. `parts` in a v1 file is an unknown key, and older readers refuse v2 with `schema_mismatch`. `kSceneFileVersion` is now 2; `kSceneFileOldestVersion` is 1.
- **Scene file v3 and .spmesh sidecars** (`CORE-6`, B5). `world/mesh_file.hpp`: `save_mesh_file()` / `load_mesh_file()`. The sidecar is little-endian binary; its provenance sits outside the hash, and every load is rebuilt through `make_mesh()`, never repaired. A mesh part is written as `scene_version: 3`, `shape: {mesh: {file, hash}}`, with the path relative to the scene file; a changed mesh is refused with both hashes. The writer never writes sidecars, so call `save_mesh_file` and set `PartDesc::mesh_file` first. `scene_from_yaml()` gains a defaulted `base_dir`. Older scenes are unchanged byte for byte. `kSceneFileVersion` is 3.
- **Mesh import** (`CORE-6`, B6). New installed target `spade::mesh_import` (`world/mesh_import.hpp`): `read_gltf()` / `read_gltf_bytes()` read .gltf/.glb into named, validated meshes in metres, one per mesh node, transforms baked, seams welded exactly. Unsupported features are `unavailable` by name; nothing is repaired.
- **Mesh distance** (`CORE-6`, B2). `world/mesh.hpp` adds `mesh_sample()` / `mesh_eval()`: exact point-to-mesh distance, signed by angle-weighted pseudonormals, through a BVH that equals brute force bit for bit. `make_mesh()` now also refuses self-intersection, wrong shell nesting and more than `kMaxMeshShells` shells.
- **Mesh mass properties** (`CORE-6`, B3). `world/mesh_mass.hpp` adds `mesh_mass_properties()`: a mesh's volume (m³), centroid and inertia about the centroid (m⁵), per unit density, in the mesh frame, with `PartInertia::tensor`'s convention. Double, deterministic, bit-identical across toolchains.
- **The lambda2 vortex criterion** (`core/lambda2.hpp`). `lambda2()` is the middle eigenvalue of S² + Ω² from a velocity gradient (1/s², below zero in a vortex core), by a fixed-sweep Jacobi solve that is bit-identical across MSVC and gcc; `lambda2_hat()` is its signed root, sign(λ₂)·√|λ₂| in 1/s. In `core/flow_volume.hpp`, S's reserved channel is now `kFlowLambda2Hat` (no size or layout change); Publish fills it from the velocity gradient (merged `cd41c31`), and the old `kFlowReserved` name is deleted (merged `ef1e7f0`): use `kFlowLambda2Hat`.
- **CPU line drawing covers every column.** `raster_cpu` lines (overlays, wireframe, streamlines) no longer skip a column when their length is not a whole number of pixels; frames that draw lines have new hashes.
