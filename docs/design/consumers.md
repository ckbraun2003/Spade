# Spade — consumers

Spade is a library. A consumer builds against the installed `spade::` package (`find_package(spade CONFIG)`) and the file formats Spade defines. **This is the only document in the library where a consumer's own rule series may appear.**

## KAT

KAT is a drone SDK and editor, and the consumer Spade was first built for. Spade was extracted from the KAT monorepo with its full history on 2026-09-28.

| What KAT uses | From Spade |
|---|---|
| Simulation, worlds, vehicles, sensors, rendering | the installed `spade::` targets |
| World description | the world-file format (`world_version`, owned by Core) |
| Session ring and replay | the snapshot format (`kSnapshotVersion`, owned by Core) |
| Scene description (what Kat compiles a build into) | the scene-file format (`engine/scene/scene_file.hpp`, owned by Core) |

**Format changes a consumer sees:**
- **The object file and add_object()** (N2, merged `b2af2eb`). `scene/object_file.hpp` reads and writes one placeable object: `object_version 1`; `object:` (the scene's per-asset block, one emitter, parser and validator); `materials:` (the materials it names that a world doesn't ship). `scene::add_object(scene, file, name, pose)` is THE way to place one, for the editor and Kat alike. It is all or nothing: identical materials are reused, conflicting ones refused naming each differing field, a taken name refused, never renamed. It's the unit for the default library's props, obstacles, gates and floors.
- **The engine's build identity** (N6, merged `41b2c68`). `spade::build_identity()` (`core/build_identity.hpp`) returns the commit (40 hex, or "unknown") and whether tracked files were dirty, taken at BUILD time; a git-less build from `git archive` still knows its commit. The installed `spadeConfig.cmake` defines `spade_GIT_COMMIT` and `spade_GIT_DIRTY` from the same stamp. `analysis::create_run_folder()` without a commit names runs by it (`<date>_<hash16>_<commit12>`, plus "-dirty" for a dirty build) and refuses an engine that can't name its commit. flow_movie's cards use the first 12 characters. `path_text`'s unprintable fallback is now "<unprintable>".
- **The model file** (N1, merged `13390f3`). `scene/model_file.hpp` reads and writes one model and, optionally, its propulsion chain: `model_version 1`; `model:` (the scene's per-model block, one emitter and one parser); `propulsion:` (every `PropulsionChain` field). It is the unit for the editor's "add a drone from a file", the default library's drones, an analysis case's `ModelRef.file`, and Kat's builder. `vehicles::validate_propulsion_chain()` is the one rule for a valid chain (chain_valid's rules plus finite values); the steady-state solvers now refuse a non-finite chain with `no_bracket`.
- **LiveRun flies its rotors, and saves** (I1, merged `74b1552`). A model with rotors now needs a `LivePropulsion` (the chain, idle and soc) at `LiveRun::start()`; a bad one is refused at start by Core's own checks. Throttle goes through `armed_duty` and `rotor_omega_for_duty` to the rotor rows, and the rows at the held body become P7a discs in the fluid step. Limits are announced, never refused or dropped: `LiveState::propulsion_flags` and `run_label()` (`run_line()` is `run_label()` then " · t = …"). `LiveRun::save()` / `restore()` build on `grid_io`; the save (version 2) pins the propulsion it flew, and another chain, idle or soc is refused by name.
- **Saving an airflow grid** (merged `9aba150`). `physics/airflow/grid_io.hpp`: `grid_to_bytes(MacGrid)` and `grid_from_bytes(bytes, into)` (little-endian: "SPADEGRD", version 1, the shape, dx's bits, then u, v, w and p as fp32), and `save_grid(path, g, step)` (written to a temp file, then renamed) / `load_grid(path, into)`. A restore goes INTO a grid `make_grid()` built for the same case and is refused by name, leaving it untouched, for a short, foreign or other-version blob or another shape, dx or length. Save only between fluid steps; scratch and P2's solids are rebuilt, never saved. A restored run continues bit for bit.
- **The throttle map and the chain's identity** (merged `cf471d6`). `vehicles::armed_duty(armed, throttle, idle)` and `vehicles::rotor_omega_for_duty(chain, duty, density, soc)` take a live run's throttle to a rotor row's `omega_cmd`: idle explicit, disarm is `omega_cmd` 0 (never `enabled`), limit flags announced rather than refused. `vehicles::propulsion_identity(chain)` is a chain's identity (TD-9), pinned by a case beside `model_identity` and `parts_identity`.
- **FlowVolume generations** (merged `085674e`). `FlowVolume` gains `uint64_t generation` (not in the header or any file format) and `next_flow_generation()`, process-unique. Publish stamps a fresh generation on success. The GL renderer reuses a volume's textures while its generation and size are unchanged; generation 0 means unknown and always uploads. CONTRACT: any code that writes `v`, `s` or the header of a volume in place, or edits a copy, must set `generation` to `next_flow_generation()` or 0, or GL may draw stale content. Debug builds refuse a mismatched reuse by name.
- **model_reach includes parts** (merged `c4cd86a`). `vehicles::model_reach()` now takes each part's farthest point (its `part_bounds()` box through its mount, plus the hub's distance for a rotor part). For a model whose parts reach past its rotors, the analysis's default box (`kDefaultBoxReaches` × reach) and the editor's pick and framing grow. Models without parts are unchanged.
- **Drawing a model's parts** (`RND-9`, merged `487d4bb`). New installed target `spade::render_parts` (`render_parts/render_parts.hpp`), linking render and vehicles. `prepare_parts(model)` builds each part's geometry once in its part frame (mesh parts as meshes; shape parts split as `scene_from_world` splits a world, union leaves tessellated and CSG roots kept for the per-pixel march); `bind_parts(prepared, posed, look, scene)` poses them each frame from `posed_parts()` into a render scene. `flow_wall` is set on body wall parts only: never on porous parts, and on rotor parts only by a flag that defaults to off.
- **One look for the airflow views** (Rendering; `render/flow_look.hpp` in `spade::render`, installed with render). `colours_over` and `volume_transfer` (transfer functions over a fixed range, without and with extinction), `add_slice` (a slice in 128 bins over a fixed range), `add_streamlines` (lines coloured by speed, or one colour) and `circle` (a closed rotor rim, on `math::cos32`/`sin32` for TD-3). The recorded films (`tools/flow_movie`) and the sandbox's tour share them, so the two look like one system by construction.
- **What a view shows** (Rendering; `render/view_mode.hpp` in `spade::render`, installed with render). A view is a `ViewBase` (shaded, wireframe, velocity, exact_sdf) plus `FlowView` layers (volume, vortex_iso, streamlines, slice, surface_cp), with stable names for menus and saved views. `supports(spec, backend, inputs)` says before a draw whether CPU or GL draws it and, if not, why, in the phrase the draw path refuses in. A test holds it to both backends' real draws, budget included (4 volume and 4 iso layers, one C_p). `apply_view` builds the spec through flow_look, replacing the scene's flow content, and returns a legend per layer (quantity, unit, map, the range the renderers resolve). Depth, normals, segmentation and per-camera field channels are "not yet". For the editor's per-view selector (Interface) and the tour.
- **Live streamlines** (Rendering, merged `a35cc81`; `render/flow_lines.hpp` and `render/view_mode.hpp` in `spade::render`, installed with render). `StreamlineOptions::max_length_diagonals` caps each direction's length in box diagonals (0, the default, is no cap, so the films and the golden are unchanged). `StreamlineOptions::live()` caps at one diagonal: the editor and the tour use it. A `ViewCache`, kept across a window's views and from frame to frame and passed to `apply_view(spec, volume, scene, options, cache)`, traces each published `FlowVolume::generation`'s lines once for every view with the same seeds and options, whatever their colours. Generation 0 traces every time. With both, a 32³ live frame of any of the editor's layouts costs 2-18 ms on the RTX 3060 Ti (`GpuGlRenderer.EditorLayoutsCost`, opt-in `SPADE_GL_LAYOUT_COST=1`).
- **Rotor discs from rotor rows** (P7a, merged `81a9437`). `physics/airflow/rotor_discs.hpp` is the one rule from a rotor to its actuator disc: centre = com + R_body·hub − grid_origin, axis = −R_body·(orient·+Y) (the air pushed against the thrust), torque = −spin·Q. `vehicles/rotor_discs.hpp` adapts one body's rotor rows and `BodyState` to it, with thrust and torque from the rows' static k_T·ω² and k_Q·ω² curves (exact in hover, not inflow-corrected in climb); a disabled row gives a zero disc. Refused by rotor index: a non-unit quaternion, a spin not in {−1, 0, +1}, a negative Q, and whatever `check_disc()` refuses.
- **Live runs and control programs** (I1, merged `ae3086d`). `analysis/controls.hpp`: `ControlProgram`, a run's controls over time, held piecewise constant, with `controls_at()`, `program_issues()`, canonical YAML (`version: 1`), `save_program()` / `load_program()` and `showcase_program()`. `analysis/live_run.hpp`: `LiveRun`, the drone-box run, with `start(resolved, model)`, `step(controls)`, `advance_frame(controls, FlowVolume&)` (frames at k/30 s of simulated time, the world origin at the box's centre), `state()`, `body()`, `run_line()` and `recorded_controls()`. The drone is held at the centre at the commanded attitude. Until the rotors are coupled, a model with rotors starts but doesn't step. `spade::analysis` now links `spade::sim` (PRIVATE).
- **spawn(vehicle) burial point** (merged after `0e9e09c`). `spawn(vehicle)` now refuses a pose whose CENTRE OF MASS is buried deeper than the model's proxy radius in the world SDF, the point contact ejects from and the one `set_body_state()` tests, instead of the design origin. Only a vehicle with a non-zero `com_offset`, spawned near a surface, can change outcome.
- **Re-posing a live body** (`Simulation::set_body_state(ref, pos, orient, vel, omega_body)`, `sim/simulation.hpp`, merged `5377d0d`). It sets a flushed body's state at a step boundary, in the body row's own frame: what `body()` returns (the centre of mass, principal axes, omega in the body frame), not `VehicleSpawn`'s design frame. The quaternion is stored as given, refused outside |q| 1 ± 2e-6. It zeroes `specific_force` and keeps the pending wrench, every sensor binding, rotor and drag row, the refs and the tick. A set body evolves bit-identically to one spawned at that state. Refused by name: a poisoned Simulation (the first mutator to refuse while poisoned), a bad or unflushed ref, non-finite values, and a buried pose (spawn's own predicate).
- **Mass from mesh** (the airframe compile, merged `d1c401d`). A part record can now take its geometry from an imported mesh: `GeometrySource::mesh` with a `mesh`, a `density` (kg/m³, no default) and a declared `min_feature`. Its mass, centre of mass and inertia then come from the mesh. The part sits at the record's placement and its mass at the mesh's centroid. A hand-entered mass, shape, size or tensor beside a mesh is refused (TD-9). With no `DragSpec`, an airframe with any mesh part is refused at drag, since the estimate cannot see a mesh's area: give a DragSpec. Every `TriangleMesh` now carries `mass_properties()` (volume, centroid and inertia per unit density, computed once by `make_mesh()`).
- **Part bounds** (merged `ae4efa3`). New `spade::Aabb` (`world/aabb.hpp`) and three host calls: `vehicles::part_bounds(const PartDesc&)`, a part's box in its part frame (a mesh part's exact fp32 vertex extremes; an SDF part's `sdf_bounds()`); `sdf_bounds(const SdfProgram&)` (`world/sdf.hpp`), a conservative box holding every point `eval()` puts in the solid, exact per primitive through its transform, box algebra for union, intersect and subtract, a smooth_union grown by k/4, padded a few hundred fp32 ulps and rounded outward; and `sdf_bounded()`, the structural check `ModelType::validate()` now uses. An unbounded solid, an empty solid, a singular transform, and a part with both forms or neither are each refused by name.
- **The run queue** (`INT-7`, W2c, merged `da35bf6`). `analysis/queue.hpp`: `enqueue_run()` and `step_queue()`, a serial queue a host steps on a timer. Its order is `runs/queue.txt`, so it survives the host closing. One run at a time, started only when its memory need (its queued progress's `memory_bytes`) plus a 6 GiB margin is free; otherwise its progress says why. A dead runner is a fault, and a cancelled queued run never starts. **Format change:** a queued run's progress.yaml now carries its memory need in `memory_bytes`.
- **The validation report** (TD-9, merged `da35bf6`). `analysis/validation.hpp` is the one reader of the validation record format (`docs/design/test-docs/01-verification.md`). `validation_report(dir)` and `validation_records(text, source)` return the newest record of each configuration: its commit and sha, date, path and config, and each measure's quantity verbatim, value, number and unit, reference, tolerance (bound and origin) and verdict (within, MISS or report only; a report-only measure has no tolerance). A malformed or unpasted record is refused with its file and line.
- **Analysis runs in their own process** (`INT-7`, W2c, merged `da35bf6`). `analysis/launch.hpp`: `launch_run()` starts the installed runner, `spade_analysis_runner` (installed into bin/ and exported as `spade::analysis_runner`), on a queued run folder. It names the runner by an explicit, absolute path and passes the arguments as an array, without a shell. The runner is detached, and the call writes `run.yaml` with the kind, the runner and the PID; a host stops a run only by that PID or by `cancel_run()`. It refuses by name a relative or missing runner, a real run ("no airflow solver yet (W1)"), a folder without its case, and a second launch. Also `cancel_run()` and `process_running()`. `RunKind`: until W1, only a dry run launches, a stand-in step with no airflow and zero loads, marked `kind: "dry-run"` in run.yaml and progress.yaml, in its log, and on the first line of history.csv. **Format change:** progress.yaml now starts with a required `kind` key, so a progress file written before this merge is refused.
- **Motor placement** (the airframe compile). Each motor now sits beside its propeller: its mass and solid are moved half the motor's extent along the thrust axis, behind the propeller for a tractor (the default) or ahead of it for a pusher (`RotorSpec::pusher = true`, new, per rotor). The reference quad's `model_identity` changes from `0x9be262bdf825ba41` to `0x78fdc769a0503ff6`, and its `parts_identity` from `0x2578117f1aa83070` to `0x1f0c49d9fd04ed42`. Stored snapshot blobs of it are therefore refused (L2), since its motors' mass and solids moved below the rotor plane, where real motors sit. Any compiled airframe whose motor has a shape changes identity the same way.
- **`spade::analysis`** (`INT-6`, merged `fc7f19d`). A new installed target, `spade::analysis`, which links `spade::vehicles` and `spade::physics`. `analysis/case.hpp` is the CFD analysis case Kat's builder reads and writes. `AnalysisCase` pins its model by file, `model_identity()` and `parts_identity()`, and holds the controls, flight, fluid, grid, each rotor's blade definition and airfoil polars, the time and the outputs. `case_issues()` lists every problem with its field. `case_to_yaml()` / `case_from_yaml()` / `load_case()` / `save_case()` read and write the `.case.yaml` (`version: 1`, canonical text; an unknown key or another version is refused). `resolve()` fills the defaults, sizes the grid, and builds the drone box's boundary conditions (`physics::airflow::DomainBc`: the wind as ambient, the floor as a wall, still in hover and rolling in forward flight). It refuses by field: a changed model (`model.identity`) or changed parts (`model.parts`) until re-pinned, a grid over the byte cap, and a wall part thinner than two finest cells. `analysis/coefficients.hpp` adds `rotor_coefficients()`, which returns C_T, C_Q, C_P and FM in hover, or J and eta in forward flight, in the rotorcraft or propeller convention, each with its definition, and `pressure_coefficient()`.
- **Analysis runs** (`INT-7`, W2a/W2b, merged `5654780`). `analysis/run.hpp`: `run_folder()` / `create_run_folder()` (`runs/<case>/<date>_<hash16>_<commit12>`, refused if it exists), and `RunProgress` with `read_progress()` / `write_progress()`. progress.yaml is replaced atomically, so a host polling it never reads a torn file. `analysis/runner.hpp`: `run_case()`, the loop the runner tool drives. It writes progress.yaml, history.csv (each column with its unit) and log.txt, and ends done, cancelled (the host makes the folder's `cancel` file; the results are partial) or faulted (named). The process side, launch(), the runner tool and the queue, lands with W2c.
- **Snapshot format v2** (module API stage 1, merged `062e1fa`). The header grows to 40 bytes and carries the configuration identity: the module set, versions and compiled order. A v1 blob is refused with the version message. A blob restores only into a simulation with the same identity (`L2`). KAT passes blobs through without parsing them, so a KAT session ring that holds v1 blobs cannot restore them after the upgrade.
- **Module API stage 3** (merged `42b352a`). The standard module set gains an `environment` module and a `dryden.sample` pass, so its configuration identity changes. A snapshot taken before this merge is refused on restore. The snapshot format itself is unchanged.
- **Design frame** (drone builder, Task B, merged `7532259`). A model type carries its design frame: `design_to_principal` and `com_offset`. `spawn` takes and `vehicle_state` returns poses in the design frame. The default is the identity frame, which changes nothing bit for bit.
- **Snapshot format v3** (drone builder, Task C, merged `7d46b6d`). The header grows to 48 bytes and carries the model registry's identity: each registered model's identity (`vehicles::model_identity`) in registration order. A blob restores only into a Simulation that has registered the same models in the same order. Register them before `restore()`, even in a fresh Simulation. A v2 blob is refused with the version message.
- **Scene file** (drone builder, Task D, merged `43eac56`). A new format: a scene holds a world reference plus placed assets and vehicles. It names its world by `world_hash()`, and composing it against another world is refused (`SCN-001`). Its text is canonical (`SCN-002`). Models register in the scene's `models` order (`SCN-005`). The first golden is `tests/golden/scenes/gate_run.scene.yaml`.
- **The airframe compile** (drone builder, `DBP-44`, merged `58abbf4`). `vehicles/airframe_compile.hpp` turns a part-built `AirframeSpec` (design frame, Kat's part-block units) into a `ModelType` in its principal body frame: `compile_airframe()`, `check_airframe()` (every problem in one list) and `airframe_propulsion_chain()`. A 4-in-1 ESC's `current_total` caps the drive current over its channels (`DBP-26`). Until a list of ESC boards lands, a total needs `channels` equal to the rotor count. The reference quad's `model_identity` is pinned and reproduced on gcc.
- **`ModelType::issues()`** (merged `58abbf4`). The installed `vehicles/model_type.hpp` gains `ModelIssue` and `issues()`, which list every problem with its element, index and field. `validate()` returns the first of them, with unchanged messages. `physics/forces.hpp` gains `DragLawCheck` and `check_drag_law()`. Both doors now run `check_drag_law()`: `ModelType::validate()` (and so `register_model()`) and `Simulation::add_drag_element` refuse a negative or non-finite area or coefficient, which they used to accept. One drag message changed: validate()'s "coeffs and local_pos must be finite" became one message per field (the drag law's own reasons for mode, area and coeffs, and a separate local_pos message).
- **UTF-8 paths in messages** (merged with `core/path-text-utf8`). Error messages name file paths in UTF-8 on every platform (`spade::path_text`, `core/path_text.hpp`). No file loader throws while reporting one: `load_gltf` used to throw `std::system_error` for a path outside the ANSI code page on Windows, and now returns `io_error`.
- **GPU admission and banded parity** (the user's ruling of 2026-10-05; merged `e146575`). Any Vulkan 1.1+ device is admitted, whatever its fp32 denormal support (`CORE-5`); no kernel requests a denormal mode (SPIR-V `P3`). `Simulation::vulkan_device_report()` (and `compute::DeviceReport` / `describe()`) says which device, driver and float settings produced a Vulkan run (`L6`). GPU results are banded against the CPU, not bit-identical (`TD-14`): about 0.01% relative at worst in-horizon, positions within micrometres, and in long or chaotic runs the two paths drift apart as any two float implementations do. Each path is deterministic on its own (CPU across MSVC and gcc; GPU per device and driver), and the CPU is the reference.
- **The IMU feels contact** (`PHY-7`). The accelerometer's specific force includes the contact response: a body resting on the ground reads `+g` up, not about 0, and an impact reads its full reaction, with no range clamp (thousands of m/s² on a hard landing). In-flight readings are unchanged. Every scene with contact has new digests. The reported velocity at rest still reads about `-g·dt` until `PHY-8`.
- **Module API stage 4: modules own their state** (merged `9763b93..`, stage 4 complete). The installed `sim/module.hpp` gains `ArrayDecl`/`Extent`, `StreamDecl`, `ConfigTableDecl`, `VehicleRows`, `ScratchDecl`, `QuantityAccess::optional` and `PassDecl::before`. `Simulation` gains `attach_row`, `module_rows<T>`, `module_array` and `config_table`. `SubstepContext::state` gives passes views of their declared state, and `StepShape` gains `arrays` and `scratch`. The standard `<module>.state` tokens are renamed (e.g. `dryden.dryden`), and `create()` refuses a set that drops or reshapes a built-in array or stream. Snapshot format stays v3; identity, schema hash and goldens are unchanged, so stored blobs still restore.
- **A misused module view poisons the Simulation** (module API stage 5 Task 1). A pass that reads its declared state with the wrong row type, for a world outside the set, or with the wrong accessor no longer gets a silent empty view: the step runs to its end and `step()` refuses, naming the module, pass and array. From then on every `step()` and `snapshot()` refuses with "state invalid since tick N: ..." until a successful `restore()` or a fresh `create()`; reads stay open. `table_rows<T>(view)` (no world) and `all_rows<T>(view)` are new in the installed `sim/state_view.hpp`. The standard set never misuses a view, so nothing changes for it.
- **`FlowVolumeHeader` gains `extrapolated_cells`**: the cells inside a solid that were written from their fluid side (so `C_p` on a surface reads wall pressure), at most `nx·ny·nz`; `validate_flow_volume` refuses a larger count by name. It is 0 for a volume with no solids.
- **Triangle mesh type** (`CORE-6`). The installed `world/mesh.hpp` adds `MeshUnit`, `mesh_unit_scale()`, `MeshInput`, `TriangleMesh` and `make_mesh()`. Only `make_mesh()` builds a mesh: it needs a declared unit, stores fp32 metres rounded once, and refuses by name, with counts, any mesh that is not a closed, oriented, 2-manifold solid. `content_hash()` is FNV-1a 64. Nothing folds it or reads a mesh yet.
- **Per-part model geometry** (`CORE-7`). The installed `vehicles/model_type.hpp` now includes `vehicles/model_part.hpp`: `PartAttach`, `PartSurface` (wall or porous; coefficients finite and ≥ 0, both 0 on a wall), `PartDesc` and `kNoPart`, and `ModelType::parts`, empty by default. `ModelIssue` gains `code` and `Element::part`, so an exhaustive switch over `ModelIssue::Element` needs a case for it. `validate()` returns the first issue's code: `capacity_exceeded` for a part shape deeper than `kMaxSdfDepth`. `register_model()` refuses a bad part by index, name and field, including an unbounded shape and a `min_feature` that is not finite and > 0. Parts are not folded into `model_identity` yet, so every identity and every stored v3 blob holds.
- **`vehicles::parts_identity(model)`**: the parts' own identity (geometry, mounts, surface, `min_feature`), a fixed constant when there are none, identical across toolchains. `model_identity` never folds parts; a CFD case pins both.
- **Posing a model's parts** (`CORE-7`). `vehicles/part_pose.hpp`: `posed_parts()`, `posed_program()` (the wall parts as one world-frame `SdfProgram`), `part_wall_velocity()`, `part_sample()` and `sample_parts()` (distance, owner, surface kind and wall velocity; a tie goes to the lower part index). `compose_transform` now lives in `world/builder.hpp`; `spade::scene::compose_transform` still names it, bit for bit.
- **A mesh as a part** (`CORE-6`, B4). `PartDesc` gains `mesh`, a `std::shared_ptr<const TriangleMesh>`. A part's geometry is exactly one of `shape` and `mesh`; otherwise it is refused at `shape`, naming the part. `part_sample()` (now in `vehicles/model_part.hpp`) returns the same `SdfSample` for either form, in the part frame. `posed_program()` refuses a mesh wall part by name; use `sample_parts()`. Not folded into the identity.
- **The airframe compile emits parts.** `PartInertia` gains `geometry` (`PartGeometrySpec`: source, name, role). A sphere, box, cylinder or tube record, and a shaped motor, ESC or battery block, becomes a body-frame wall part, with `min_feature` set to its smallest dimension. A propeller never does, and `source = none` opts a record out. Mass, inertia, drag and the reference quad's identity are unchanged.
- **Scene file v2** (`CORE-7`). A scene whose models have parts is written as `scene_version: 2`, with a `parts` list per model (`tests/golden/scenes/parts.scene.yaml`). A scene without parts is still version 1, byte for byte. This build reads both. `parts` in a v1 file is an unknown key, and older readers refuse v2 with `schema_mismatch`. `kSceneFileVersion` is now 2; `kSceneFileOldestVersion` is 1.
- **Scene file v3 and .spmesh sidecars** (`CORE-6`, B5). `world/mesh_file.hpp`: `save_mesh_file()` / `load_mesh_file()`. The sidecar is little-endian binary; its provenance sits outside the hash, and every load is rebuilt through `make_mesh()`, never repaired. A mesh part is written as `scene_version: 3`, `shape: {mesh: {file, hash}}`, with the path relative to the scene file; a changed mesh is refused with both hashes. The writer never writes sidecars, so call `save_mesh_file` and set `PartDesc::mesh_file` first. `scene_from_yaml()` gains a defaulted `base_dir`. Older scenes are unchanged byte for byte. `kSceneFileVersion` is 3.
- **Mesh import** (`CORE-6`, B6). New installed target `spade::mesh_import` (`world/mesh_import.hpp`): `read_gltf()` / `read_gltf_bytes()` read .gltf/.glb into named, validated meshes in metres, one per mesh node, transforms baked, seams welded exactly. Unsupported features are `unavailable` by name; nothing is repaired.
- **Mesh distance** (`CORE-6`, B2). `world/mesh.hpp` adds `mesh_sample()` / `mesh_eval()`: exact point-to-mesh distance, signed by angle-weighted pseudonormals, through a BVH that equals brute force bit for bit. `make_mesh()` now also refuses self-intersection, wrong shell nesting and more than `kMaxMeshShells` shells.
- **Mesh mass properties** (`CORE-6`, B3). `world/mesh_mass.hpp` adds `mesh_mass_properties()`: a mesh's volume (m³), centroid and inertia about the centroid (m⁵), per unit density, in the mesh frame, with `PartInertia::tensor`'s convention. Double, deterministic, bit-identical across toolchains.
- **The lambda2 vortex criterion** (`core/lambda2.hpp`). `lambda2()` is the middle eigenvalue of S² + Ω² from a velocity gradient (1/s², below zero in a vortex core), by a fixed-sweep Jacobi solve that is bit-identical across MSVC and gcc; `lambda2_hat()` is its signed root, sign(λ₂)·√|λ₂| in 1/s. In `core/flow_volume.hpp`, S's reserved channel is now `kFlowLambda2Hat` (no size or layout change); Publish fills it from the velocity gradient (merged `cd41c31`), and the old `kFlowReserved` name is deleted (merged `ef1e7f0`): use `kFlowLambda2Hat`.
- **CPU line drawing covers every column.** `raster_cpu` lines (overlays, wireframe, streamlines) no longer skip a column when their length is not a whole number of pixels; frames that draw lines have new hashes.
