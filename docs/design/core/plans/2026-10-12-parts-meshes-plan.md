# Per-Part Model Geometry and Triangle Meshes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `ModelType` carries its solid geometry part by part, each part an exact shape at a body-frame mount, rigid or turning with a rotor, and a wall or porous surface. A posing rule turns a vehicle's parts into one world-frame SDF, with a wall velocity at any point. Parts are read and written in the scene file, and the airframe compile emits them from the inertia shapes it already has. Then triangle meshes join `SdfProgram` as a part's exact geometry (`CORE-6`): a validated mesh type, exact BVH distance with a deterministic sign, mass properties, a binary sidecar named by the YAML, and readers for glTF, binary STL, OBJ and 3MF. The standard identity, the schema hash, every model identity, every golden and every stored v3 blob stay where they are.

**Architecture:**
- **Part A, the first step (`CORE-7`, note §3).** `vehicles/model_part.hpp` holds `PartAttach`, `PartSurface` and `PartDesc`; `ModelType::parts` is empty by default and refused by name. `vehicles/part_pose.hpp` is the one CPU posing rule: per-part world poses, their union as one world-frame `SdfProgram`, the wall velocity, and a per-part sampler that is the CPU twin of stage 7's raster (`CORE-8` §5.2). `compose_transform` moves down to `world/` so `vehicles/` never includes `scene/`. The scene file gains `parts` (scene version 2, written only when a model has parts). The airframe compile turns sphere, box, cylinder and tube inertia shapes into wall parts.
- **Part B, triangle meshes (`CORE-6`, note §2 option B).** `world/mesh.hpp`'s `TriangleMesh` is immutable and shared. `make_mesh()` declares units and refuses anything that is not a closed, oriented, 2-manifold, non-self-intersecting solid. It derives a two-level BVH and angle-weighted pseudonormals, never stored. `mesh_sample()` gives exact distance, sign and gradient. A part holds an `SdfProgram` or a mesh, and `part_sample()` answers for either. Meshes live in `.spmesh` sidecars named in the YAML by path and content hash. Readers live in their own target, `spade_mesh_import`, outside the library the step links.

**Tech Stack:** C++23, GoogleTest through ctest, MSVC + Ninja presets. No kernel, binding, mirror or Slang layout change. Part B task 8 adds miniz and pugixml (MIT) only if the lead approves them (open question 5).

## Decisions this plan makes

**Bound by the approved note** (the lead's answers, 2026-10-12), not reopened here:
- mounts are in the body frame, and authors work in the design frame through `AirframeSpec`;
- parts replace the single collider. There is no `ModelType::collider` in code (it was a proposal in `2026-10-12-airflow-demo-core-inputs.md`), so nothing is removed;
- `role` is a free label;
- parts fold into the identity only from stage 7;
- ψ is Physics';
- the compile turns inertia shapes into geometry automatically;
- the porous model is Physics' (answered, below).

**Physics' porous answer (2026-10-12), binding.** `PartSurface` is `{kind ∈ {wall, porous}, inv_permeability (1/K, 1/m²), inertial_coeff (C₂, 1/m)}`.
- Both coefficients are finite and ≥ 0, and both are 0 on a wall, refused by name otherwise.
- The grid applies the Darcy–Forchheimer sink over the part's cells. Nothing else lives on the part.
- **No drag element changes in this plan.** Whether a part's drag element applies follows the airflow coupling mode, which is the airflow module's call.
- **ψ** is a per-rotor array that the airflow module declares (Physics' P11). This plan takes ψ as an input and stores none.

**How the identity and the blobs stay put.**
- `model_identity` is untouched (`model_identity.cpp:50-89`). Its header's fold note gains one line beside `visual_ref`: "parts are NOT folded until a step reads them (stage 7, `CORE-7`)".
- An empty `parts` writes nothing anywhere: no YAML key, no count, no byte. Every existing model, scene text and blob is therefore unchanged.
- **The cost if this is wrong:** folding parts now would move the reference quad's pin as soon as Task A4 emits parts, and refuse every stored blob of a part-bearing model, for no change in any step. The fold, with the mesh content hash and the per-model identity cache, is stage 7's, bundled with stage 7's own identity change (note §1.6).

**The posing rule (Task A2).** One CPU rule in `vehicles/`, which stage 7's GPU raster mirrors (`TD-9`).
- **Pose.** B = (`pos`, `orient`) from `BodyState`. A rigid part is posed as X = B · M. A part on rotor k is posed as X = B · H_k · R_y(s_k ψ_k) · M, with H_k = (`local_pos`, `local_orient`). Each mount quaternion is normalized first. R_y takes `cos32`/`sin32` of s_k ψ_k / 2. `world_to_part` is `transform_of(SdfPose{X})`, so a part is posed bit for bit as the builder poses a primitive.
- **Wall velocity** at x: `vel + ω × (x − pos) + s_k Ω_k a_k × (x − h_k)`, with ω = `orient * omega_body` (`BodyState::omega_body` is body-frame, `layout.hpp:124`). For a rigid part the last term is zero.
- **Two forms, one rule.** `posed_program()` is the note's "one world-frame `SdfProgram`": the union of the posed **wall** parts, joined as `compose()` joins an asset (`compose.cpp:96-133`), so the demo hands its solver the same form as the static world SDF. `sample_parts()` evaluates each posed part in its own frame and keeps the smallest distance, with **a tie going to the lower part index** (`CORE-8` §5.2). That is the CPU twin of stage 7's raster. It covers porous parts, and Task B4 extends it to mesh parts, which have no `SdfProgram` form. The two agree within rounding (pinned, Task A2).
- **The filter** is the note's: `rigid_only` for the disc and actuator-line tiers, or `all`.
- **ψ** is in radians, any finite value (`sin32` is ≤ 1 ulp for |ψ| ≤ 100, `fp32_math.hpp:186-188`). The caller wraps it. If Physics stores an integer phase (`CORE-8` §5.3), the airflow module converts it, once, before posing.

**`compose_transform` moves down** (note §3), from `scene/compose.{hpp,cpp}` (`compose.hpp:53`, `compose.cpp:25-27, 155-166`) to `world/builder.{hpp,cpp}`, beside `transform_of` (`builder.hpp:64`).
- The move is byte-identical, and so is its private `is_identity`. `spade_world` already links `spade_fp_strict` (`engine/CMakeLists.txt:272`), as `spade_scene` does.
- `namespace spade::scene { using spade::compose_transform; }` stays in `compose.hpp`. The consumer smoke (`tests/consumer/main.cpp:141`) and `test_scene_compose.cpp:260-292` call it qualified and compile unchanged. They are the move's pins.

**Additions beyond the note.** Each is small and needs the lead's yes (open questions 1–3):
1. **`PartDesc::min_feature`** (m, ≥ 0; 0 means not declared). `CORE-8` D5, signed after the note, refuses a part the grid cannot resolve, and calls "the smallest feature" "part metadata, from the per-part note". The note defines none. Adding it now keeps the API, the YAML and the compile's record from moving a second time. Nothing reads it before stage 7.
2. **An unbounded shape is refused.** A plane or a heightfield that no intersect bounds would make a part fill half of space. The rule is a postfix walk: primitives are bounded except `plane` and `heightfield`; `union` and `smooth_union` are bounded if both operands are; `intersect` if either is; `subtract` if its left operand is.
3. **Blocks yield geometry too** (Task A4). The note's table covers "inertia shape sphere, box, cylinder or tube" for every record. A shaped motor (at each hub), ESC or battery becomes a wall part. The propeller never does, because its disc is mass only (note §1.5). The motor's shape is centred on the hub (`airframe_compile.cpp:186`), so its solid straddles the rotor plane: open question 3.

**Other decisions.**
- **Where the types live.** A new header, `vehicles/model_part.hpp`, holds `PartAttach`, `PartSurface`, `PartDesc` and `kNoPart`. `model_type.hpp` includes it, so the note's "the installed `model_type.hpp` gains" holds for every includer. `composite_inertia.hpp` includes it too, for Task A4's record.
- **`ModelIssue` gains `code`** (last member, default `invalid_argument`), and `validate()` returns the first issue's code. That lets a shape deeper than `kMaxSdfDepth` keep `capacity_exceeded`, as `validate_scene()` does (`scene_file.hpp:129`). `Element` gains `part`, after `imu_mount`.
- **The compile's record is `PartInertia`.** The note says "the installed `airframe_compile.hpp` part records gain a name, a role, a shape and a surface". `AirframeSpec::parts` is a `std::vector<PartInertia>` (`airframe_compile.hpp:187`), declared in `composite_inertia.hpp`. So `PartInertia` gains one trailing member, `PartGeometrySpec geometry{}`, which `composite_inertia()` never reads. One record per part (`TD-9`); every caller compiles unchanged.
- **The record's frame.** `position` and `orientation` stay the part frame. For an inertia shape the frame's origin is the centre of mass, as today. A given shape is authored in that frame. For mass from geometry (Task B4), the centre of mass is derived from the geometry.
- **Scene version 2 is written only when a model has parts.** A scene with none is written as version 1, byte for byte. The reader reads 1 and 2, and accepts `parts` only in a version-2 file. So a version-1 reader says `schema_mismatch` ("upgrade") rather than "unknown key" (note §1.7). Task B5 does the same for mesh parts with version 3.
- **A part's YAML shape is `shape: {sdf: {transforms, nodes}}`.** It uses the world file's SDF encoding (`yaml_text.hpp:462, 487, 506, 528`), behind `check_sdf_representable` (`yaml_text.hpp:629`), with no `node_materials` key (render data, refused on a part). Task B5 adds the alternative `shape: {mesh: {file, hash}}`.

**Triangle meshes (Part B).**
- **The sign test: angle-weighted pseudonormals** (Bærentzen and Aanæs, 2005), **not the generalized winding number.**
  - The sign of (p − c) · n at the closest point c is provably correct when n is the angle-weighted pseudonormal of the closest feature: the face normal, an edge's two face normals summed, or a vertex's corner normals weighted by corner angle. The precondition is a closed, oriented, 2-manifold surface with no self-intersections.
  - A query is then the BVH search plus one dot product: `+ − × /` and `sqrt`, fp32, mirrorable on the GPU later, and bit-identical across MSVC and gcc under `spade_fp_strict`.
  - A winding number needs `atan2` per triangle per query, which `TD-3` forbids on a state path. It is also O(n) per query exactly, or approximate with a hierarchy, and its one advantage, robustness to open or defective meshes, buys nothing: such meshes are refused (`L6`; no silent repair).
  - Corner angles are computed once per mesh, at `make_mesh()`, in double, by a Spade-owned `atan2` built from `+ − × /` and `sqrt`: range reduction plus a fixed polynomial with pinned constants and a pinned Horner order (`core/math_ops_f64.hpp`, internal and not installed). Pseudonormals round to float once.
  - **The precondition is enforced, not assumed:** combinatorial checks in Task B1, then self-intersection and shell nesting in Task B2.
  - **Shell nesting without a winding number.** Each shell's signed volume gives its orientation σ = ±1. For each shell s, sum σ_t over the other shells t that contain s's lowest-index vertex, using the sign test on t alone. An outward shell needs the sum to be 0. An inward shell, a cavity, needs it to be 1. That is exactly "the winding number is 0 or 1 everywhere", in arithmetic.
- **Ties are canonical.** The closest triangle is the minimum of (squared distance, triangle index), so the answer does not depend on the traversal order: a BVH query equals brute force bit for bit (pinned). Each edge is projected in its canonical direction (lower vertex index first), so a shared edge gives the same bits from both triangles.
- **The BVH is two-level:** shells, then triangles, so a query can be restricted to one shell (the nesting check). It is built top-down by a median split along the longest centroid axis, sorted by the total order (centroid coordinate, triangle index), with leaves of at most 4. The bounds are fp32 min and max of the vertices (exact). It is derived at `make_mesh()` and never stored.
- **Positions are fp32, in metres, in the part frame,** rounded once from double after the unit scale. Indices are `uint32`, three per triangle, counter-clockwise seen from outside.
- **Units are part of construction.** `MeshInput::unit` defaults to `unspecified`, which `make_mesh()` refuses. glTF is metres by its specification. 3MF declares its unit. STL and OBJ take one from the caller.
- **Topology is by position.** `make_mesh()` refuses two vertices at one position, and the readers weld exact duplicates (value equality, so −0 equals +0) before calling it. No tolerance weld (open question 8).
- **The content hash** is FNV-1a 64 over the vertex count, the triangle count, every position's float bits and every index, little-endian, spelt byte by byte as `model_identity` is. It is computed once. It is what the YAML names, and what stage 7 folds.
- **Mass properties** use Eberly's polyhedral integrals (divergence theorem), in double, in triangle order, about the bounds' centre to limit cancellation, then shifted to the centroid.
- **Storage.** A mesh lives in a `.spmesh` sidecar: magic, version, counts, a provenance block outside the hash (source, unit, tolerance: `CORE-6` D records its tolerance there), positions, indices and the content hash.
  - The YAML names the sidecar by a relative forward-slash path and by the hash, as a scene names its world (`SCN-001`). A mismatch is refused with both hashes.
  - At run time the engine reads sidecars only. The readers are import tools that write sidecars, and so will the STEP converter.
- **Readers.** They go in a new target, `spade_mesh_import`, with headers in `world/` (open question 7). Each returns named objects, every one built by `make_mesh()`.
  - **glTF is a new geometry reader.** `render/gltf.cpp` is render-only: `meshes[0]` only, no node transforms, no `.glb` (`render/gltf.hpp:41-49`), and it lives in `spade_render`, which the step must not depend on (`L5`). Rendering may later rebase `render::load_gltf` on Core's reader (open question 4).

**This plan departs from the note in six places:**
1. `posed_parts()` returns the posed frames. `posed_program()` gives the note's one world-frame `SdfProgram`, and `sample_parts()` gives stage 7's per-part rule (above).
2. `min_feature`, the unbounded-shape refusal, and block geometry (above).
3. The surface's fields are Physics' names, `inv_permeability` and `inertial_coeff`, not the sketch's `viscous_resistance` and `inertial_resistance`.

6. Mesh parts are written as scene version 3, so a version-2 reader says "upgrade".

struct PartSurface {

    float inv_permeability = 0.0f;  // porous: 1/K, 1/m^2 (Darcy); finite, >= 0
