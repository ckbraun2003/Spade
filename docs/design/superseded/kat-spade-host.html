Design specification · seventeenth spec · approved

Kat — Spade Sim Host & Training Connectors

M1b's substance: the real C5 sim host — kat_host_spade.dll — wrapping the Spade engine behind the same six-call frame ABI the editor already drives, plus the training connectors and the physics/aero configuration schema family that make legacy training dynamics mirrorable on Spade. The editor needs zero code changes; that is the proof the seam was real.

✅ APPROVED v1.0 — drafted 2026-08-18 · signed off 2026-08-19 decision series HS1–HS12 consumes C2 · C5 (TA1–TA6, B1/B10/B11/B15) · engine spec + Addendum A · config spec · catalog CP8/CP18 · training TR1/TR3/TR15 Spec I of the spade↔editor integration program (Specs II–III: viewport-cameras · default-content)
§0

What this document is

The 2026-08-18 spade↔editor integration session ruled the program shape: adapter first with interim CPU presentation; the S7 Vulkan renderer swaps in later behind the same frame ABI (user-ruled, option A of three). This spec pins the adapter: placement, engine-agnosticism rules, the C5→Spade call mapping, the conformance bar, the interim presentation raster, the physics/aero config schemas, and the six training connectors (F-1…F-6) the user ruled into scope. It designs seams and contracts; implementation detail lands with the writing-plans plan.

Precedence & series

Decision series HS1–HS12. This spec implements C5 (it does not amend it — the one C5 widening this program carries, camera slots, lives in Spec II as a TA-series amendment; the experimental batch surface in HS9 is deliberately non-normative). Where it touches other specs' territory it does so by recorded coordination: the airframe extension is a CP-series amendment owned jointly with the catalog program; the HS8 config rulings feed batch 4's Q2/Q3.

§1

HS1 — Identity & placement

HS1 · placement (user-approved DP-A, 2026-08-18)

The Spade-backed sim host lives at dronesim/spade/, building kat_host_spade.dll, sibling to dronesim/fake/. The fake is retained as the CI/conformance reference and the deterministic lightweight host for editor tests. Spade is consumed via find_package(spade CONFIG) against an installed tree and statically absorbed into the host DLL — one self-contained artifact, loaded by the editor through the existing DLL-path setting, exactly as the fake is today.

Rejected: hosting inside spade/ — the engine tree stays kat-free by charter; the adapter is kat-side by definition.

The C5 header home is unchanged: dronesim/include/kat/kat_host_abi.h. The host advertises the same KATHOST_ABI_MAJOR 1; a conformance-identical implementation is the point.

§2

HS2 — Engine-agnosticism, three hard rules

HS2 · engine-agnosticism (user-ruled 2026-08-18)

Rule 1 — Spade stays kat-free. The engine tree gains zero kat dependencies, schemas, or concepts. Everything kat-flavoured lives in the adapter.

Rule 2 — the kat side stays Spade-free. No spade header is includable outside dronesim/spade/, enforced at the CMake level (the same mechanism class as the editor's kat_assert_no_widgets()), mirroring the existing "no kat_* symbol outside core/sim/ + core/validate/" rule. Every consumer — editor, trainer, SDK — reaches simulation only through C2/C5 and schema'd artifacts.

Rule 3 — connectors bind to schemas, not structs. The adapter is a resolver: it consumes the schema'd configuration artifacts (HS8) and maps them to Spade PODs privately. A different engine would implement the same resolution against the same artifacts.

G2 stands (user-ruled 2026-08-18)

Engine-agnosticism holds at the contract layer, not the format layer: the world file and the sim-physics vocabulary remain Spade-defined, versioned as C5 contract artifacts (config spec G2, world schema v1 user-frozen 2026-08-12). Any conforming host must read them; no engine-neutral world format is created.

§3

HS3 — The C5 → Spade call mapping

One kathost handle owns one spade::Simulation with world_count = 1 (HS3a): the editor host is single-world; training's many-world parallelism never rides the editor's C5 path (TR1/TR3 — it is the trainer's loop; see HS9/F-5). All calls single-threaded per handle (B11); frame-buffer reads legal from any thread between acquire and release.

§4

HS4 — Conformance bar: the fake's own suite, zero editor changes

HS4 · definition of done

The Spade host passes the editor-skeleton program's C5 conformance suite unchanged — every case the fake passes, byte-for-byte semantics. Additionally: (a) render-cadence invariance proven against Spade's own golden digests (stepping bit-identical for any render cadence including none); (b) determinism — same seed, same commands ⇒ byte-identical state at equal tick counts, cross-checked against Spade's scenario goldens; (c) the editor binary needs zero code changes for milestone M-2 — connecting Spade is a settings line (the DLL path), not a build.

Known fake deficiencies the real host retires and must test as retired: the fake's missing lateral thrust authority (the M1b item named by the TR15 parity-gate artifact) — the Spade host's plant is the real rotor/drag model resolved from the airframe descriptor (HS8a).

§5

HS5 — Interim presentation raster

HS5 · interim raster (user-approved sequencing ruling, 2026-08-18)

Presentation frames are produced by a port of the fake's deterministic, Qt-free CPU rasterizer (dronesim/fake/raster.cpp) reading live Spade state: poses from world_bodies, wireframes from the same WorldDesc SDF program, spawn markers, body markers. Opaque BGRX per TA1's MN-14 floor. It is explicitly interim — D10-strangler style — and is retired when S7's FramePool reaches parity behind the same kathost_render/frame_acquire calls. Renders happen on the sim thread at most once per presentation interval, after step, renders-drop-first under load (B11/A5).

The raster port may optionally draw wireframe hulls from resolved visual meshes (Spec III's resolver) where cheap; it must never become a rendering program of its own — feature growth beyond "recognizable + correct poses" waits for S7.

§6

HS6 — The vision lane: synthetic features per A8

Per engine Addendum A8 (user-ruled 2026-08-10): the 25 Hz camera lane is satisfied by host-synthesized analytic feature buffers derived from the SDF world geometry — the fake's camera architecture promoted to the real host. They ride the sensor surface (B15: no ref ports; image-like payloads cross via kathost_sensor_poll with host-owned fixed-maximum buffers), synthesized inside stepping (B1/A1), deterministic and seeded. Rendered camera pixels arrive with S7's camera-sensor seat and change nothing about this transport. The training spec §4's in-loop geometry-sensor obs kind (depth/range from the SDF + the true-SDF privileged shortcut) rides this same machinery and is declared/versioned per that spec.

§7

HS7 — Faults

The host installs compute::set_error_sink and maps engine faults to the sticky C5 status codes (KATHOST_E_DEVICE_LOST for backend loss, E_BAD_STATE/E_INVALID per class). The editor's existing B8 behaviour — freeze last presented frame, banner, session dead, all instances disarmed — needs no change. Backend selection (cpu | vulkan) is opaque backend config per A7(b): result-neutral by contract, surfaced as a host setting, never scene content.

§8

HS8 — The physics/aero configuration schema family

Per the user's 2026-08-18 ruling, the connectors bind to established configuration structures, and this program defines the schema'd homes for physics and aerodynamics params — under the configuration spec's schema law (authored once → generated C++ struct, Python dataclass, validator bindings, editor form, docs page; x-kat-units everywhere; provenance mandatory on dimensional values).

HS8a — Airframe descriptor extension (CP-series amendment, coordinated with the catalog program)

HS8a · one plant vocabulary

CP8's airframe.json (schema in runtime/schemas/, semver'd with C1/C3) is extended with the full plant vocabulary this program needs: multi-element aero (per-element drag bodies — fuselage/arms/rotors — with geometry-derived placement; aero rung 1), rotor model (tau, thrust/torque coefficients, spin layout, thrust ceilings, airspeed-thrust decay), rate-loop constants (gain vector, first-order lag tau, omega ceilings — the CTBR inner loop), sensor mounts + sigmas, inertia, proxy radius. The Spade adapter resolves descriptor → vehicles::ModelType; the legacy mirror (HS9/F-3), the trainer's env adapter, and the editor's generated forms all read the same artifact. Mesh-derived values (aero rung 2) use the existing closed provenance vocabulary — source: "derived" with a method record naming the mesh + tool — no config-spec amendment needed.

CP18 discharge — the axis transform is stated here, once

This spec's implementation writes down the Y-up/Z-up (and handedness) transform between the catalog/obs-registry frame and Spade's Y-up right-handed frame in exactly one place — the descriptor resolver — and the HS9/F-3 parity harness is its executable proof. HOST_AIRFRAME_MISMATCH (rung ③) becomes a real check in the Spade host: world plant vs descriptor divergence errors at arm.

Aero rung 3 — runtime mesh-based aerodynamics (panel/BEM methods) — is explicitly staged out (user-approved DP-C): a future engine S-phase with GPU-parity implications. The descriptor schema is written so rung 3 slots in as new element kinds without breaking rungs 1–2.

HS8b — Scene sim-physics block (N3, editor-owned schema)

HS8b · sim content lives in the scene (user-ruled DP-F, 2026-08-18 — settles batch-4 Q2/Q3)

dt_ns, substeps, and seed live in the scene document (N3) — they are result-affecting simulation content, versioned with the scene. (The as-built editor already has sim_settings.dt_ns/seed; this ruling confirms it and adds substeps.) The scene's placeholder wind block is replaced by the real schema'd instance-physics block: contacts (restitution, friction, baumgarte, slop, proxy radius), grid (cell size), turbulence (Dryden scales/sigmas/reference airspeed). N4 keeps paths, mode, trust anchors, and the opaque backend block. Sensor noise sigmas live in the airframe/sensor descriptor (plant side), not the world file. These rulings are recorded for batch 4's Q2/Q3 absorption per the propagation discipline.

A7's partition becomes the editor's config-surface law: content knobs (above) are authored, versioned scene config with units + provenance; the opaque backend block (device selection, workgroup size, capacities) is host settings whose result-neutrality is contractual (every admitted knob owes an invariance test). Pass-schedule shape and integrator order are not configurable, ever.

§9

HS9 — Training connectors (F-1 … F-6)

User-ruled 2026-08-18: the connectors exist now; training itself is implemented in its own session. Everything below binds to contracts and schemas per HS2 Rule 3.

F-1 · Headless full-loop rollout proof

The Spade host runs the complete STEPPED loop headless — C2 runtime + C5 Spade host, no editor process — proven by a T1-class rollout test and the headless CLI path. This is SD5's "headless STEPPED rollouts" socket; TR15's protocol names this substrate verbatim ("Spade-backed C5, never dronesim/fake").

F-2 · Python rollout harness (test-tier seed, not the glue home)

A thin ctypes harness over the two C ABIs — load kat_runtime + kat_host_spade, create/step/poll/snapshot from Python — living under train/ as test-tier infrastructure, explicitly not a public surface. SD3's one-glue-home rule stands: the public session/build/train glue is designed once by the SDK implementation plan; this harness is its living evidence and feedstock, scheduled for absorption there (SD7 schedules the glue migration). Divergence between this harness and the eventual glue is a defect in the harness.

F-3 · Legacy-dynamics mirror

HS9/F-3 · the oracle (user-ruled 2026-08-18)

The oracle is the legacy training plant, code-as-executed — controller/dynamics/quadrotor.py + quadrotor_env's rate lag — the dynamics the 42.6% result actually trained against, including airspeed-thrust decay and the inner rate loop. The converter maps configs/physics.yaml + configs/drones.yaml (competition_aigp) → the competition-700 airframe.json, carrying the legacy record's own provenance (measured dates, joint-fit annotations) through x-kat-provenance, with method legacy-mirror. Every authored key the legacy code ignored or transformed — the interface-side C++ plant's 5 dropped airspeed/rate keys included — lands in a discrepancy report: documented decisions, never silent drops.

The dynamics-parity harness drives identical command traces through the legacy plant and through Spade (via F-2), applies the HS8a axis transform, and compares trajectories within tolerance bands that are measured then pinned with provenance (execution-record discipline). Bit-parity is not the claim — RK4 vs Spade's integrator differ by design; the claim is bounded, documented dynamical equivalence. This is the evidence machinery that makes TR15's "comparable performance on Spade physics" adjudicable. It does not adjudicate the gate: RI-1/RI-2 were open user rulings (active-work queue #11); both were dissolved by structures TS17, 2026-08-26, which withdrew the number they turned on.

F-4 · Action-path connector (CTBR → rotors, no fork)

Legacy training's action space is CTBR with the rate loop inside the plant; Spade takes rotor omegas. The reference CTBR→rotor path is the catalog's control.rate component's math — fixture-verified, never a reimplementation — driven by the descriptor's rate-loop constants (HS8a), shipped trainer-side in the env-adapter home. Parity-tested against the legacy rate lag (rate_gain/rate_tau/omega_max as executed).

F-5 · Batched-training seam (experimental — RATIFIED, see the stamp below)

HS9/F-5 · experimental extension (user-ruled 2026-08-18)

kat_host_spade.dll exposes a small kathost_x_batch_* surface — create an N-world set, step all, per-world state/sensor access — explicitly non-normative (the _x_ namespace marks it experimental), smoke-tested through the F-2 harness. TR3's ruling (world-index batching is training's parallelism axis) gets a working connector without pre-empting seat S2, which designs the real contract with this as living evidence. The fake does not implement it; no conformance case references it.

⚠ STATUS SUPERSEDED (structures TS11, user-ruled 2026-08-26; stamped 2026-09-01). The non-normative / experimental status claim is withdrawn: TS11 (twenty-second spec, DRAFT but later and higher in the precedence chain, and user-ruled) promotes kathost_x_batch_* to the ratified C5 training seam, and master ships that promotion. dronesim/spade/batch_x.h's own header records the change verbatim — "the RATIFIED C5 TRAINING SEAM (22nd spec, TS11, USER-RULED 2026-08-26 — amends C5)", and: "This surface began as the experimental, non-normative quartet the 17th spec's HS9/F-5 introduced for seat S2. TS11 promotes it." The surface has since grown kathost_x_batch_create_configured over a per-world kathost_world_config_t array (merge 000b8f8, 2026-09-01), which is where domain randomization reaches the simulation. What is NOT struck — the rest of F-5 still holds as written: the reach is unchanged (the symbols are still resolved by name from kat_host_spade.dll and are still not declared in kat/kat_host_abi.h, which stays byte-identical); the fake still does not implement it; and dronesim/tests/conformance_c5/ still contains no reference to it — both re-verified 2026-09-01. Seat S2 is likewise unpre-empted. Only the words experimental and explicitly non-normative are false now.

F-6 · Observation connector

The demo program's obs-block assembler (7 registered blocks) is wired to Spade-host state behind the same catalog §2.2 declaration; the existing obs-parity test extends to the Spade substrate — observations, like dynamics, are mirrorable. Touching train/ is coordinated through the active-work register with the paused demo-training program, never a silent edit.

HS10 — Verification

  • C5 conformance suite: fake and Spade host both green, same cases (HS4).
  • Determinism/digests: same-seed byte-identity at equal ticks vs Spade goldens; render-cadence invariance including cadence none.
  • Snapshot round-trip across the ABI (save → restore → identical continuation digests).
  • TA5 poll semantics incl. ring-wrap drop reporting.
  • Descriptor resolution goldens: airframe.json → ModelType, axis-transform cases, HOST_AIRFRAME_MISMATCH both directions.
  • Dynamics-parity harness: pinned command-trace corpus, measured-then-pinned bands, discrepancy report as a tracked artifact.
  • B10 frame-pool semantics: one case per call class (restore, reset, load_world, despawn, camera_set).
  • All testing local until the Actions quota resets (standing user directive).
