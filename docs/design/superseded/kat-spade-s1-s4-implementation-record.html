§4

Verification record

Method

  • Per-task gate: fresh implementer per task → independent review on the task diff before merge — spec compliance and code quality both required. Physics tasks received re-derivation reviews: the reviewer re-derives the math from first principles (momentum theory, covariance identities, discrete-bias references) rather than reading the implementation as its own proof. No task in the program needed more than one fix round.
  • Mutation-kill evidence: where a test's value is discrimination (frame swaps, sign errors, branch selection), fix rounds required demonstrated red-under-mutation — the recurring S1–S4 pattern was correct math whose original tests couldn't distinguish a swapped variant (identity-orientation/unit-mass blindness, three separate tasks); each was closed with discriminating tests plus verified kill tables.
  • Golden discipline: digests regenerate only with root-cause provenance in the file header; the two structural regenerations (T18 vehicle arrays, T19 sensor arrays) were each proven to be pure walk-suffix continuations — old digest reproducible with the new arrays excluded — rather than trusted.
  • Stage gates: S1/S2/S3/S4 each ran the full suite on both presets plus kat-side checks (pytest, mkdocs strict, non-spade diff audit). The S4 gate added the whole-plan opus review over all 49 commits, which mechanically verified the global constraints (zero fp64/wall-clock/random_device hits, v1-freeze exact) and triaged the entire deferred-minor backlog: zero must-fix, everything else ticketed or dropped with a written ruling.

Checkpoints and demos

Checkpoint №1 validated the four physics scenes (drop, bounce, shower, gate) and produced the three user amendments above. Checkpoint №2 validated the flight scenes: hover (in-trim quad, orbit camera), wind (Dryden moderate — visibly wandering altitude, deliberately level), flight (scripted takeoff through the gate ring, ~t≈8 s crossing), swarm (four worlds batched, four vehicles). Scene validation evidence included per-scene screenshots, FPS ranges, and full-window garbage-geometry sweeps; the hover test's non-vacuity is anchored by an IMU assertion that is physically incapable of passing on a frozen or free-falling body (+g requires rotor thrust through force_acc).

§5

The first Linux run — cross-platform parity, earned

The PR was the first time any non-MSVC compiler built the engine (an honest caveat carried since S1: "portability by inspection"). It found three defects, escalating in depth:

  • Name-lookup portability: a file-local apply() helper resolved to std::apply via ADL on libstdc++ (hard error) while MSVC picked the local — renamed ADL-proof.
  • Warning strictness: a -Wredundant-move under gcc's -Werror.
  • A real bit-parity defect: exactly one golden scenario diverged on Linux, with fp-contraction already off. Per-array/per-tick digest instrumentation localized it to the Dryden array at tick 0 — before any physics ran. Root cause: MSVC's CRT and glibc disagree by 1 ulp on cosf/sinf at two specific arguments consumed by Box-Muller during Dryden init. Only one scenario failed because an init-time draw lands in registered state unattenuated, while per-substep draws pass through a ~7·10⁻³ noise gain that rounds 1-ulp differences away — the other three scenarios passed by luck, which is worse than failing. Body trajectories were bit-identical on both platforms for all 901 ticks throughout.
The fix set the standing rule.

IEEE 754 mandates correct rounding for + − × ÷ √ only; libm transcendentals differ across implementations. core/fp32_math was born: log32/sin32/cos32 built from mandated ops only, exhaustively verified ≤1 ulp over all 2²⁴ inputs, and the goldens regenerated with provenance naming the old values as MSVC-libm artifacts — no tolerance loosened, no per-platform goldens, no digest weakening. The remaining sites of the same class (std::exp in Dryden, the exp-map's sin/cos, plus two sites the original exception list missed) are being retired in S5 Task 1, before the corpus is re-baked as data. The generalized lesson is recorded as L13.
